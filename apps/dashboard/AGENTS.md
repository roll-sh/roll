# dashboard — agent guide

The roll website and dashboard on **TanStack Start** (`@tanstack/react-start` 1.169, React 19,
Vite 8, SSR). The APIs changed during 2025: check the installed package's types or
tanstack.com/start before relying on what you remember.

## Run it

- `pnpm --filter dashboard dev` — Vite on port 3000. Add `--host 0.0.0.0 --port <p>` to reach it
  from another machine; hostnames other than localhost need `ROLL_DEV_ORIGINS` (comma separated,
  `.example.com` for every subdomain), which becomes Vite's `server.allowedHosts`.
- `pnpm --filter dashboard build` then `start` — `vite build` writes `dist/client` and
  `dist/server/server.js`; `server.mjs` serves them on Node with srvx (`-H <host> -p <port>`, or
  `HOST`/`PORT`; all interfaces and 3000 by default). Hashed assets under `/assets/` are cached for
  good.
- Env: `VITE_ROLL_API` is the API as browsers reach it, built into the client (default
  `http://127.0.0.1:7070`). `ROLL_API_URL` is how the server reaches rolld, read at runtime
  (`serverApi()` in `lib/roll-api.ts`; read it per request, never at module scope).
  `VITE_ROLL_TASKS_TOKEN` is a tasks token for local development.

## Routes

- File routes in `src/routes` (`$param`, `$` for the rest of the path as `_splat`, `index.tsx`,
  `route.tsx` for a layout). A folder or file starting with `-` is ignored by the router, so the
  storage pages under `/dashboard/storage/-/…` live in `[-]/` (brackets escape a character).
- `src/routeTree.gen.ts` is generated by `vite dev` and `vite build` and committed: rebuild after
  adding, moving or renaming a route, and commit the result. Route files export only `Route`
  (other exports break code splitting): shared constants go in `src/lib`.
- Every new top-level route or file in `public/` is a reserved owner name
  (`lib/reserved-names.ts` and `crates/code-control/src/names.rs`); tests on both sides read
  `src/routes` and `public/`.
- Titles and metadata come from each route's `head()` through `lib/head.ts` (`pageHead`, which
  adds "· roll"); public repo pages use `repoHead` from `lib/code-meta.ts`.
- Links: `@/components/link`'s `Link` takes the `href` the page built (path, query and hash, or
  `?query` on the current page) and hands it to TanStack's router. Navigate in code with
  `useNavigate()({ href })`; read the path with `useLocation({ select })`, params and search with
  the route's own `Route.useParams()`/`Route.useSearch()`. Search params are plain strings, kept
  exactly as written (`lib/search.ts`): don't add a `validateSearch` that drops keys (the router
  redirects to the URL it would have built).

## Data

- Dashboard pages are client components that talk to rolld from the browser (`lib/*-api.ts`).
- Public pages (owners, repos, shares) load on the server: a route's loader calls a
  `createServerFn` (in `lib/code-server.ts`, `lib/agents-server.ts` or the route file), which runs
  in-process for the first request and over RPC on client navigations, always against
  `ROLL_API_URL`. Return plain JSON-shaped data (a server function's result is serialized; type
  untyped API JSON as `Json` and decode it in the loader). Include `now` so relative times match
  between the server and the browser.
- Existence decides the status before anything renders (`lib/public-pages.ts`): throw
  `notFound()` for a 404 and `redirect({ href, statusCode: 308 })` for a renamed repo. The
  `$owner/$repo` frame looks the repo up in `beforeLoad` and its pages read it from
  `Route.useRouteContext()`; keep the check there.
- Server routes (`server: { handlers }` in a route file) answer the git smart HTTP proxy
  (`lib/git-proxy.ts`, bodies streamed both ways) and the share preview image
  (`agents/s/$id/opengraph-image.tsx`, satori + resvg). Give every method a route doesn't serve
  an `ANY` handler (405), or it falls through to the page renderer.
- `src/start.ts` holds the request middleware (CSRF for server functions, the trailing-slash 308).

## Tests

`pnpm --filter dashboard test`: vitest (`*.test.ts` in node, `*.test.tsx` in jsdom) and the
`node --test` suites in `test/`. `src/test/setup-dom.ts` stands the router's `Link`, `useNavigate`,
`useRouter` and `useLocation` in for components rendered without a router; server functions need
Start's request context, so test the functions they call (`fetchRepo`, `repoOr404`) instead.
