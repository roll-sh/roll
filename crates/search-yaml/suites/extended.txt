# The extended YAML suites: Elasticsearch 9.5.5's module and x-pack plugin suites that the
# rest-resources zip's test/free doesn't hold, each with the cluster its Gradle build gives it.
# Read by scripts/search-yaml-suites.sh (fetch-extended, es-extended-baseline, roll-extended).
# Only names and settings live here; the tests are downloaded into target/search-yaml/ and never
# committed (they are not Apache-licensed).
#
# Format: <suite> <profile> <source> [option...]
#
# source  a project directory of the v9.5.5 source tree (target/search-yaml/es-9.5.5-src), whose
#         tests are <source>/src/yamlRestTest/resources/rest-api-spec/test; or zip:<dir>, a
#         directory of the rest-resources zip's rest-api-spec/test. `:a,b` keeps only those
#         subdirectories (several test classes of one project that run on different clusters);
#         `:-a,b` keeps all but those.
# profile how the test cluster is set up (security and license; see es_profile in the script):
#   plain           security off, trial license (Elasticsearch's integ-test distribution clusters)
#   basic           security off, basic license
#   security        security on over HTTP, trial license; the runner logs in as `login`
#   security-basic  security on, basic license
#   plugins         plain, plus the official plugins of plugins/* installed
# options (repeatable):
#   setting=<key>=<value>   a node setting (also given to search-dev as -E)
#   roll=<key>=<value>      a node setting only search-dev gets (what roll needs to behave like
#                           the test cluster, which Elasticsearch has no setting for)
#   jvm=<-Dkey=value>       a JVM system property (Elasticsearch only)
#   users=<u:p:roles>,...   file-realm users (roles `|`-separated); search-dev gets them as
#                           roll.security.file_users
#   login=<user>:<password> who the runner logs in as (security profiles; default
#                           x_pack_rest_user:x-pack-test-password, which every cluster defines;
#                           a user listed without roles gets the test clusters' _es_test_root)
#   admin=<user>:<password> who cleans up between tests, when the suite's class runs its tests as
#                           a less privileged user (ESRestTestCase.restAdminSettings)
#   roles=<file>            a roles.yml for the file realm (source-relative)
#   config=<dest>:<file>    a file copied into the node's config directory (source-relative, or
#                           suites/... for one of ours in crates/search-yaml/suites/es-config:
#                           service_tokens holds a generated token1 like XPackRestIT's)
#   runner=<arg>            a search-yaml run argument (what the suite's Java test class adds)
#   memory=<size> heap=<size>  container limits for this suite's cluster (default 1536m / 768m)
#
# Suites that share a profile and options run on the same clusters in one runner invocation.
#
# Not run: repository-azure / -gcs / -s3 (cloud fixtures), gpu (a GPU), stateless (serverless modules), multi-node and mixed-cluster qa projects, the qa projects that
# only rerun platinum directories with other users (graph, ml, text-structure with security),
# enrich (no tests of its own), discovery-* and store-smb plugins, x-pack/qa (multi-cluster,
# third-party services).
