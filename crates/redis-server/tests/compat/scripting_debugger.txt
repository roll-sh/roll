# The Lua debugger (SCRIPT DEBUG YES|SYNC): an EVAL becomes a session driven by debugger
# commands, each answered with an array of status lines; the session ends with <endsession>,
# the EVAL's reply, and the connection closing. SYNC sessions keep their changes, YES sessions
# run on a copy (a fork in Redis) and the client is gone from the server meanwhile.

# ---- inside a transaction: the session ends it (later replies dropped; YES: in the copy). The
# truncated EXEC reply that follows <endsession> isn't read here (the harness can't parse it).
@conn 15
DEL ex1 ex2 ex3
SCRIPT DEBUG SYNC
MULTI
SET ex1 v
EVAL "redis.call('set','ex2','v')\nreturn 1" 0
SET ex3 v
EXEC
c
